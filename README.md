# 手机网页版德州扑克（单机 · 6 人桌）

无限注德州扑克，固定盲注 1/2，起始筹码 200（也就是 100 个大盲），
一张 6 人桌，1 个真人 + 5 个机器人。
纯前端、零依赖、可安装为 PWA，直接跑在手机浏览器里。

**在线玩：https://yingqi0906.github.io/mobile-holdem/**

## 更新线上版本

改完代码直接 `git push`，GitHub Pages 会自动重新构建，一两分钟后生效。

如果网络需要代理才能访问 GitHub，注意 **git 不会自动读取 Windows 的「系统代理」设置**，
必须显式告诉它，否则只会看到 `Recv failure: Connection was reset`：

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'   # 端口按你代理软件实际的监听端口改
git push
```

想省事就写进仓库配置（只影响这个仓库，不动全局）：

```bash
git config http.proxy http://127.0.0.1:7897
```

万一某天代理也不通，还有个完全不依赖 `github.com` 的兜底方案 —— 直接走
REST API 发布，而且会顺带把本地分支对齐到远端提交：

```bash
node tools/deploy-github.mjs <用户名>/mobile-holdem --token-file <令牌文件路径>
```

令牌用 classic token 的 `repo` 权限，用完记得撤销。

## 跑起来

```bash
npm run serve     # 启动本地静态服务器
npm test          # 跑规则引擎的单元测试
npm run sim       # 让 6 个机器人互相对打 2000 手，输出统计
```

`npm run serve` 会打印两个地址：`localhost` 给电脑，局域网 IP 给手机。
手机和电脑连同一个 WiFi，在手机浏览器打开那个 IP 即可。

> 必须用 HTTP 打开，不能双击 `index.html`。因为项目用的是原生 ES module，
> 浏览器的 `file://` 协议不允许跨文件 import。

装到主屏：iOS Safari 用「共享 → 添加到主屏幕」，Android Chrome 用「安装应用」。
装完之后是全屏无地址栏的，并且离线也能打开。

## 分享给朋友试玩

```bash
npm run share     # 起服务器 + 开一条 Cloudflare 快速隧道，打印公网 https 地址
```

不需要注册任何账号，第一次运行会自动下载 `cloudflared`。把打印出来的
`https://xxx.trycloudflare.com` 发给朋友即可。按任意键停止。

**这条链接只在你这台电脑开着、且这个脚本还在运行时有效**，适合"现在就发给朋友试试"。
想要一个长期能用的地址，需要部署到静态托管（GitHub Pages / Cloudflare Pages /
Netlify / Vercel 都行，这个项目是纯静态的，直接传上去就能跑）。用哪个我可以帮你配。

## 代码结构

```
src/core/     纯逻辑，不认识 DOM
  cards.js      牌的整数编码（0..51）与互转
  evaluator.js  牌型评估：5 张压成一个整数，7 张取最强 5 张
  engine.js     牌局状态机：applyAction(state, action) -> state
  ai.js         蒙特卡洛胜率 + 性格参数的机器人
  rng.js        crypto 随机数 / 可播种随机数 / 洗牌
src/ui/app.js 渲染、点击翻译、定时器驱动
tests/        node:test 写的规则测试
tools/sim.js  批量模拟，用来看 AI 行为是否合理
probe.mjs     用无头 Chrome 量出真实手机视口下的元素几何（见下）
```

改样式之前建议先跑一次 `node tools/probe.mjs`：它会用 CDP 把视口设成
390×844 这种真实手机尺寸（Windows 上 Chrome 的窗口宽度有 500px 下限，
直接开窗口量不到），然后把每个关键元素的坐标、有没有互相遮挡、有没有溢出
视口全部打印出来。第三个参数可以切换到 `raise`（加注面板）或 `result`
（结算面板）状态。**靠数字判断布局，比靠眼睛猜靠谱得多。**

**引擎是纯函数式的**：每个行动都克隆一份状态、返回新状态，不碰任何全局变量。
好处是联机的时候天然就是「同步动作」而不是「同步状态」，而且测试可以直接
拿状态对象断言，不必起浏览器。

引擎里还维护着一份**整局账本** `state.session`：每个人的累计买入、每手结束后的
筹码余额、最高/最低、赢过的次数。它刻意放在引擎而不是界面里 —— 以后做联机时，
服务端跑的是同一套引擎，这份账本可以直接随状态同步给每个客户端，不需要再写
第二份统计逻辑。筹码面板里的那张多人走势图，就是纯粹从这份账本画出来的。

## 已经按 TDA 规则处理好的坑

这些是德州扑克实现里最容易写错的地方，都有对应的单元测试：

- **边池**：按每个人的累计投入分层，短码玩家不参与他够不到的边池。
- **无人跟注的部分自动退回**：你下注 500、对手只有 200 全下，那 300 原样还你。
- **最小加注**：加注增量不得小于上一次的加注增量，下限是一个大盲。
- **短码 all-in 不重开下注轮**：不足额的 all-in 只提高当前注额，
  已经行动过的人只能跟或弃，不能再加注。
- **单挑特殊规则**：两人时按钮位就是小盲，翻牌前先行动、翻牌后后行动。
- **平分余数**：彩池不能整除时，余下的筹码按「按钮左手第一个」的顺序分发。
- **前注型大盲**：大盲筹码不够时，其他人仍然要按完整大盲跟注。

`npm test` 里有 24 个测试，其中两个是重点：

- **随机对抗**：多张桌子轮流打到散场，累计 800 手，每手结束都校验筹码守恒 ——
  这是验证边池有没有算错最有效的手段。
- **界面冒烟**：用极简 DOM 桩把整个界面跑起来，打完 5 手牌，专门抓
  "元素取成了 null"这类接线错误。

`npm run sim` 则是看 AI 表现得像不像人。一个健康的 6 人桌大概长这样：

```
平均底池 479　亮牌结束 29.4%　看到翻牌 42.5%　平均行动 5.8 次/手
单次决策平均耗时 1.8ms
```

亮牌率太低说明桌子太紧没有 action，太高（比如 70%+）说明大家在无脑跟注。
调 `src/core/ai.js` 里的 `BOT_PRESETS` 和翻前门槛，然后重跑这个命令即可。

## 机器人怎么打

每个机器人随机分配一种性格（岩石 / 跟注站 / 紧凶 / 松凶 / 均衡），
决策流程是：

1. 用蒙特卡洛模拟跑 200～400 次，估算自己对抗当前人数对手的胜率；
2. 和底池赔率比较，再叠加紧度、激进度、诈唬频率三个参数；
3. 偶尔慢打大牌、偶尔诈唬，避免打法被一眼看穿。

这不是最优策略（最优要上 CFR 之类的求解器），但已经能打出像样的对局。
想调难度就改 `src/core/ai.js` 里的 `BOT_PRESETS`。
